# pdf-layout-translate 📄✨

**把任何排版精美的 PDF / Word 原样翻成中文 —— 版式不动、图表不跑、文字可选中。**

给 AI Agent 用的翻译工艺技能：不重排版，只换字。

---

## 为什么需要它

你一定遇到过这种情况：

> 找到一份排版漂亮的英文报告/论文/白皮书，扔给翻译工具，出来的却是——
> 图表全跑位、表格散架、多栏变单栏、字体变大变小，原来 190 页的书翻译完只剩"参考价值"。

市面上的文档翻译大多走"提取文字 → 重排 → 输出"的路线，版式注定保不住。
这个技能换了一条路：**原版打底 + 文字覆盖翻译**——

```
┌─────────────────────────────────────────────┐
│  原始 PDF（原样保留：版式/图表/配色/页眉页脚）  │
│  + 抹掉原文文字层（redaction，不碰任何图形）    │
│  + 同坐标原位覆盖中文（字号/颜色/粗细/对齐一致） │
└─────────────────────────────────────────────┘
```

效果：翻开成品和原书"长得一模一样"，只是字变成了中文，还能选中、搜索、复制。

## 实战战绩

190 页英文投行蓝皮书（几百个图表、表格、散点图）整本翻译：

- ✅ 全书版式与图表位置零变动，逐页像素比对通过
- ✅ 正文可选中、可搜索
- ✅ 嵌入中文字体后成品从 400MB+ 压到 **~13MB**（字体子集化）
- ✅ 31 处复杂图表盲区（图例/轴标/图内标签）逐处定点补翻，高倍渲染验收
- ✅ 公司名、指数名、化学式按约定保留原文

## 技能内含什么

`SKILL.md` 是一份可以直接喂给 Agent 的完整工艺手册，包括：

| 模块 | 内容 |
|---|---|
| 开工判断 | 文字版 vs 扫描版识别；扫描版自动降级做中文对照版，不硬覆盖 |
| 主流程 | 四元键全文索引 → 按块翻译 → redaction 抹字 → 同坐标覆盖中文 |
| 字体子集化 | pyftsubset 实操命令，整本 400MB+ → 2MB 级 |
| 逐行验收 | 英文残留 / 留白漏字双判据机器扫描，段首段尾、页首页尾重点扫 |
| 数字对账 | 原书与成品数字 token 集合必须一致，防翻译时错位 |
| **24 条踩坑实录** | 每一条都付过真金白银的学费（见下） |
| Word/DOCX 支持 | .doc/.docx 原位替换（表格/页眉页脚/文本框全扫），嵌入图片走光栅图工艺，默认转 PDF 交付 |
| 执行组织与巡检 | 长任务拆分/分批落盘/子代理安排与定时巡检兜底：断了能续、断了必被发现、发现即接管 |

### 24 条坑，随便挑几条尝尝

- 🏷️ **四元键索引**：块/行编号跨批次不稳定，键错了整页坐标错位（v1 翻车实录）
- 🎨 **彩色字会被"找灰字"扫法漏掉**：图表里和图形同色的标签，得换"任一通道够暗"判据，再按行分段把字和箭头线分开
- 📉 **测量坐标账本会过期**：跨会话交接的坐标可能整体偏移或抄错——执行前逐条回原书重测，原书才是唯一权威
- 🔲 **盖板会误伤**：表格边框线被切出 25 段断口、金色图例线被盖、圆牌色差……盖板避让要覆盖到图例色标、色块边缘、装饰线
- 🐘 **字体不子集 = 400MB+**：CJK 字体直接内嵌，成品大到发不出去
- 👻 **盖板遮字 ≠ 删字**：残字还躺在文字层里，复制出来是乱序幽灵文本
- 🌀 **巨字糊页**：回填宽度超限时绝不拉伸，降字号或换行
- 🧹 **行尾残句**：`"n."`、`". A"` 这种孤片段会绕过整句翻译，需要专门扫描清理
- 🔀 **跨格同块文字会串格**：相邻单元格/图框的文字常在同一个文本块里，按块回填会把 A 格内容写进 B 格（目标格空白、邻格多行）——要按原书 span 逐格重写；且同款图表设计会在全书重复出现，发现一处就该扫全书一次修完
- 📝 **Word 的坑在别处**：python-docx 只遍历正文段落会漏掉表格/页眉页脚/文本框；Word 把一句话拆成多个 run 要按段落聚合；转 PDF 前必须核对字体，缺字体会导致版式漂移
- ……以及段首段尾整行丢失、光栅图盲区、混排字号串行、按原书样式重绘特殊文字等

## 快速开始

### 安装

```bash
git clone --depth 1 https://github.com/jia295339800/pdf-layout-translate.git
```

把 `SKILL.md` 放进你的 Agent 用户技能目录，如 `user-skills/pdf-layout-translate/`。
对支持 Skill 机制的 Agent（如灵光），装完后说"**用 pdf-layout-translate 翻译这份 PDF，保持版式不变**"即可。

### 依赖

- Python：`PyMuPDF (fitz)`、`numpy`、`fontTools`（pyftsubset）
- 中文字体：思源黑体/宋体（Noto CJK）Regular + Bold，需做子集
- OTF ↔ TTF 转换：fontTools 手写转换脚本（PyMuPDF 对 OTF 兼容不佳）

### 对人类使用者的说明

这个技能面向 Agent 使用——它不是现成软件，而是一套"怎么把活干对"的操作规程。
如果你想手动照着做，`SKILL.md` 里的代码片段可以直接抄。

## 工作流程（五步）

1. **样张先行**：先挑 2–3 个代表页（正文/图表/封面）出样张，用户确认后才动整本——确认过的方案就是验收标准
2. **建索引**：全文块索引（四元键 pno/bidx/lidx/span，全局唯一），记录每个 span 的 bbox/字号/颜色/粗细
3. **翻译**：按块聚合送翻，payload 携带四元键回填定位；数字/人名/代码/品牌名保留，术语全书统一
4. **覆盖**：redaction 抹字（绝不碰图形）→ 同坐标 insert_text 覆盖中文，baseline 取 `y1 − 0.22 × size`
5. **验收**：逐行扫描（漏翻/漏补双判据）→ 数字对账 → 4x 渲染裁片目检 → 发布更新原产物

## FAQ

**Q：成品打开后版式真的完全一样吗？**
A：本技能的全部努力就是这个目标——不重排版，只换字。逐页像素比对是发布前的强制验收。

**Q：扫描版 PDF 怎么办？**
A：自动降级为"原页影印 + 中文译文页"的中文对照版，不硬覆盖（没有文字层可抹）。

**Q：图表里的英文标签也翻吗？**
A：默认保留（图例、品牌标识、缩写）；用户确认需要翻的关键标签逐个定点覆盖，逐处验收。

**Q：能翻别的语言吗？**
A：工艺上同源，把目标字体和字符集换掉即可，但手册按中文化场景沉淀，换语言需自行调整。
